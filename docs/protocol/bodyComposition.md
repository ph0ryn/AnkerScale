# 体組成の計算

[全体索引](../protocol.md)

取得値から12項目（体重・BMIと10項目の体組成）を求める計算経路と式を説明します。

## 計算に必要な入力

体脂肪率はBLE通知から直接読む値ではなく、測定値と登録プロフィールから計算します。

```text
体重・インピーダンス
  + 身長・年齢・性別・通常／アスリート設定
  → 機種に対応した計算SDK
  → 体脂肪率・脂肪量・筋肉量・水分率・骨量・基礎代謝など
```

| 入力 | BestHealth系での扱い |
| --- | --- |
| 体重 | kg。計算関数の入力ではkg×10を整数化 |
| 身長 | cm。計算関数の入力では整数化 |
| 年齢 | 「現在の年−生年」。誕生日前後を考慮した満年齢ではない |
| 性別 | 女性=0、男性=1 |
| 設定 | 通常=0、アスリート=1 |
| インピーダンス | 通知のencrypted impedanceを渡し、SDK内部でΩへ復号 |

T9120では、平文のimpedance欄が1〜65534の範囲にあることを
体組成値の保存条件に使います。計算そのものへ渡すのは別のencrypted impedance欄です。
多くの結果は小数1桁で保存しますが、SDK内部にも整数化処理があり、最後に四捨五入するだけでは一致しません。

## 機種別の計算系統

| 機種 | 計算経路 |
| --- | --- |
| T9120、T9146 C1、T9147、T9148、T9149、T9150、T9130 | BestHealth。encrypted impedanceとプロフィールを入力 |
| T9146・通常設定 | Holtek。encrypted impedanceとプロフィールを入力 |
| T9146・アスリート設定 | BestHealth |
| T9140系 | 別の計算関数。身長m、体重kg、男性=0／女性=1、年齢、impedance raw÷1000を入力 |

T9140は性別コードと入力単位も異なるため、BestHealth用の入力をそのまま使えません。
以降の式はBestHealth系に適用します。Holtek・T9140の内部計算式とiOS版は対象外です。

## 12項目と計算の関係

| 項目 | 単位 | 計算に使う値 |
| --- | --- | --- |
| 体重 | kg | 通知から取得した体重 `W` |
| BMI | kg/m² | 整数化した体重 `R`、身長 `H` |
| 体脂肪率 | % | `R`、`H`、年齢、性別、設定、復号後インピーダンス |
| 水分率 | % | 上書き前の体脂肪率、性別、設定 |
| 筋肉率 | % | 筋肉量の整数値、`R` |
| 骨率 | % | 出力された骨量、整数化前の体重 `W` |
| 基礎代謝 | kcal/日 | `R`、`H`、年齢、性別、設定 |
| 内臓脂肪レベル | レベル | `R`、`H`、年齢、性別、設定 |
| 除脂肪量 | kg | `R`、脂肪量の整数値 |
| 脂肪量 | kg | 上書き前の体脂肪率、`R` |
| 骨量 | kg | 共通中間値 `T`、性別、設定 |
| 筋肉量 | kg | `R`、脂肪量と骨量の整数値 |

体重は測定値であり、残りの項目を以下の式で求めます。
骨率の分母には`R / 10`ではなく、SDKへの変換前の`W`を使います。

## BestHealth系のインピーダンス復号

encrypted impedanceは、ビットを組み替えてマスクを差し引くことで復号できます。
この復号はBLE接続認証のAESやMAC由来鍵を使いません。

```python
def decode_impedance(encoded):
    if encoded == 0xFFFFFF:
        return 0xFFFF
    mixed = (encoded & 0xF00) | ((encoded >> 16) & 0xFF)
    mask = 4 * (encoded & 0xFF) + ((encoded >> 12) & 0xF)
    # 負値も0方向へ切り捨てる。
    return int((mixed - mask) / 2) & 0xFFFF
```

平文rawをΩへ換算する際は、対応するencrypted impedanceの復号結果と照合します。
平文欄の換算係数は、機種と通知形式に応じて扱います。

## BestHealth系の入力変換と有効範囲

計算関数は、プロフィールと測定値を次の整数表現へ変換して受け取ります。
式の分岐は変換後の値で判定します。

| 記号 | 意味 | 変換・範囲 |
| --- | --- | --- |
| `W` | 変換前の体重kg | T9120の通常測定では通知の体重raw÷100 |
| `R` | 0.1 kg単位の体重 | float32のkg値を10倍し、0方向へ整数化。100〜2000 |
| `H` | 身長cm | float32のcm値を0方向へ整数化。90〜220 |
| `A` | 年齢 | 整数、6〜99 |
| `Z` | 両脚インピーダンスΩ | 復号した整数、200〜1200 |
| `S` | 性別 | 女性=0、男性=1 |
| `M` | 設定 | 通常=0、アスリート=1 |

`R`はuint16、`H`と`A`はuint8、復号前インピーダンスはuint32として渡されます。
flagsのbit 0が`S`、bit 1が`M`です。範囲は変換後の値についてのもので、
範囲外の値を固定幅整数へ丸め込むことを正当な入力処理とは扱いません。

| 戻り値 | 意味 |
| --- | --- |
| 0 | 成功 |
| 1 | 年齢の範囲外 |
| 2 | 身長の範囲外 |
| 3 | 体重の範囲外 |
| 4 | 性別コードの不正 |
| 5 | 通常／アスリートコードの不正 |
| 6 | 復号後インピーダンスの範囲外 |

性別・設定コードの検証はSDKの呼び出し境界で行われます。
計算関数は途中まで出力を書いてからエラーを返す場合があります。
体脂肪率などの出力は戻り値0のときに採用し、範囲外入力の途中結果は使いません。

## BestHealth系の体脂肪率の式

以下は男女・通常／アスリート設定を含む体脂肪率の計算分岐です。
HoltekとT9140の別系統の式には適用しません。

### 共通の中間値

```text
T = 0.032 × R + (9.058 × H² / 10000 + 12.226) − 0.0068 × Z − 0.0542 × A
```

性別と年齢から補正値`D`を選びます。年齢の境界は50歳以上を含みます。

| 性別 | 年齢 | `D` |
| --- | --- | --- |
| 男性 | 全有効範囲 | 0.8 |
| 女性 | 50歳未満 | 9.25 |
| 女性 | 50歳以上 | 7.25 |

```text
L = T − D
```

`L`は計算途中の値であり、最終出力の除脂肪量とは異なります。

### 体重・身長による補正

男性は次の補正だけを適用します。

| 体重 | 操作 |
| --- | --- |
| `R < 610`（61.0 kg未満） | `L = L × 0.98` |
| `R >= 610` | 変更なし |

女性は先に体重補正を適用し、その結果へ身長補正を適用します。

| 体重 | 操作 |
| --- | --- |
| `R < 500`（50.0 kg未満） | `L = L × 1.02` |
| `500 <= R <= 600` | 変更なし |
| `R > 600`（60.0 kg超） | `L = L × 0.96` |

| 身長 | 操作 |
| --- | --- |
| `H > 160`（160 cm超） | `L = L × 1.03` |
| `H <= 160` | 変更なし |

50.0 kgと60.0 kgは女性の体重補正を行わない範囲に含み、160 cmでは身長補正を行いません。
男性の61.0 kgでは0.98倍を行いません。

### 通常／アスリート設定の補正

まず脂肪量に相当する中間値`F`を求め、アスリート設定の場合は性別に応じて補正します。

```text
F = R / 10 − L
```

| 設定 | 操作 |
| --- | --- |
| 通常・男女共通 | 変更なし |
| 男性・アスリート | `F = F × 0.778 − 0.93` |
| 女性・アスリート | `F = F × 0.992 − 1.5` |

### 制限・整数化と派生値

```text
Q = trunc(clamp(F × 10000 / R, 50, 750))
体脂肪率[%] = Q / 10

脂肪量の整数値 B = (Q × R) div 1000
脂肪量[kg]       = B / 10
除脂肪量[kg]     = (R − B) / 10
```

`trunc`は0方向への整数化、`div`は整数除算です。
通常の式による体脂肪率は5.0〜75.0%に制限してから小数1桁へ切り捨てます。
脂肪量はこの整数化済みの`Q`から計算し、さらに0.1 kg単位へ切り捨てます。
除脂肪量も整数化後の脂肪量を使います。

## 体重とBMI

```text
体重[kg] = W
BMIの整数値 I = (10000 × R) div H²
BMI[kg/m²] = I / 10
```

BMIは整数化した体重と身長で求め、小数1桁へ切り捨てます。
`W / (H / 100)²`を最後に四捨五入する計算とは丸め方が異なります。

## 水分率

体脂肪率の整数値`Q`から、水分率の整数値`U`を求めます。

```text
U = (7 × (1000 − Q)) div 10
U = ((U <= 500 なら 102、それ以外は 98) × U) div 100
```

アスリート設定では、さらに次の補正を適用します。

| 設定 | 操作 |
| --- | --- |
| 通常・男女共通 | 変更なし |
| 男性・アスリート | `U = trunc(U × 0.996 + 4)` |
| 女性・アスリート | `U = trunc(U × 0.985 + 9)` |

```text
U = max(U, 350)
水分率[%] = U / 10
```

## 骨量と骨率

体脂肪率の補正前に求めた共通中間値`T`を使います。

```text
N = trunc(T × 0.5158 − (男性なら 1.802、女性なら 2.4569))
K = N + (N > 22 なら 1、それ以外は −1)
```

アスリート設定では、`K`に次の整数を加えます。

| 条件 | 加算値 |
| --- | --- |
| `K < 20` | 1 |
| `20 <= K < 30` | 2 |
| `K >= 30` | 3 |

通常設定ではこの加算を行いません。

```text
骨量[kg] = K / 10
骨率[%]  = (骨量[kg] / W) × 100
```

骨率は出力された骨量を使い、float64で計算してから保存時に小数1桁へ丸めます。

## 筋肉量と筋肉率

脂肪量の整数値`B`と、補正済みの骨量の中間整数値`K`を使います。

```text
C = R − B − K
筋肉量[kg] = C / 10
筋肉率[%]  = trunc(C × 1000 / R) / 10
```

筋肉率の乗除算にはfloat32を使います。
筋肉量の表示値から率を逆算して丸め直さず、中間整数値`C`から計算します。

## 基礎代謝

性別ごとに次の式を使います。`R`はkgではなく0.1 kg単位の整数です。
括弧内の加減算を左から順に行ってから整数化します。

| 性別 | 整数値 `E` |
| --- | --- |
| 男性 | `trunc(((1.4916 × R + 877.8) − 0.726 × H) − 8.976 × A)` |
| 女性 | `trunc(((1.0204 × R + 864.6) − 0.3934 × H) − 6.204 × A)` |

アスリート設定では、整数化後の`E`に補正を適用します。

```text
アスリート設定: E = trunc(E × 1.16 − 149)
基礎代謝[kcal/日] = max(E, 500)
```

## 内臓脂肪レベル

性別と体重・身長の条件によって中間値`V`を求めます。
各行の加減算は括弧に従い、同じ深さでは左から順に行います。

| 性別 | 条件 | `V` |
| --- | --- | --- |
| 女性 | `5 × H − 130 >= R` | `((−0.0024 × H + 0.691) × R / 10 − 0.027 × H) + 0.07 × A − 10.5` |
| 女性 | それ以外 | `0.07 × A + (50 × R / (1.45 × H + 0.1158 × H² − 120) − 6)` |
| 男性 | `0.16 × R + 63 > H` | `0.15 × A + (30.5 × R / (0.0826 × H² − 0.4 × H + 48) − 2.9)` |
| 男性 | それ以外 | `((−0.0015 × H + 0.765) × R / 10 − 0.143 × H) + 0.15 × A − 5` |

アスリート設定では、さらに次の補正を適用します。

| 補正前の範囲 | 操作 |
| --- | --- |
| `V < 2` | `V = 1` |
| `2 <= V < 10` | `V = V − 2` |
| `10 <= V < 20` | `V = V × 0.8` |
| `V >= 20` | `V = V × 0.85` |

```text
内臓脂肪レベル = trunc(clamp(V, 1, 50))
```

通常設定ではアスリート補正を省き、同じ制限と整数化を行います。

## 演算精度と出力

整数除算や明示した型変換を除き、SDK内の式はfloat32で計算します。
定数や各演算の結果にもfloat32の丸めが入ります。
加算の並べ替え、途中でのfloat64化、積和演算へのまとめ直しは、
整数化の境界で結果を変える可能性があります。
出力時の整数値÷10もfloat32で行い、その値をアプリ側のdoubleへ渡します。
骨率の式はアプリ側のfloat64演算です。

多くの割合とkg値は保存時に小数1桁へ丸めます。
途中の`trunc`・`div`と、保存時の丸めは別の処理です。

## SDK内の固定条件による上書き

通常の計算が終わった後、次のどちらかの条件に一致すると、体脂肪率を66.0%、
水分率を72.0%へ上書きします。

| 性別 | 年齢 | 身長 | 体重 | 通常／アスリート |
| --- | --- | --- | --- | --- |
| 女性 | `A = 20` | `H = 190` | `R = 300` | 両方 |
| 男性 | `A = 20` | `H = 90` | `R = 1000` | 両方 |

上書き時に脂肪量や除脂肪量などを再計算する処理はなく、
それらは上書き前の`Q`に基づく値のままです。全出力を上書き後の体脂肪率から再計算すると、
SDKと異なる結果になります。インピーダンスの範囲検証はこの後にも行われるため、
固定値が書かれたことだけで成功とは判断できません。
