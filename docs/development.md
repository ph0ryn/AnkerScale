# 開発と検証

## 開発環境

MoonBitツールチェーンと、Clangを利用できるXcodeまたはCommand Line Toolsが必要です。

macOS連携にはCoreBluetoothなどのSDKが必要になります。
実行対象のmacOS最低バージョンと署名・配布方法は、ネイティブ接続層の検証で確定します。

## C FFIの検証

MoonBitのnativeターゲットでは、ツールチェーンやビルドモードによって
Cバックエンドと新しいnativeバックエンドの選択が異なる場合があります。
C FFIの検証では、公式に用意された環境変数でCバックエンドを明示します。
この変数は各コマンドにだけ適用され、プロジェクト全体の固定設定にはなりません。

```sh
MOONBIT_NEW_NATIVE=0 moon check
MOONBIT_NEW_NATIVE=0 moon test
MOONBIT_NEW_NATIVE=0 moon build
MOONBIT_NEW_NATIVE=0 moon run cmd/main
```

設定の根拠は[MoonBitのFFIドキュメント](https://docs.moonbitlang.com/en/latest/language/ffi.html)
を参照してください。FFI導入時には開発・リリースの両方でリンクと実行を確認します。

## 検証事項

### BLE接続層

MoonBitからC ABIを通してCoreBluetoothを呼び、BLE機器の検出結果を受け取ります。
Objective-Cのオブジェクトやコールバックの寿命が適切に管理されることを確認します。

実機の名前・識別子・広告情報が得られ、停止後に処理が残らないことを確認します。
Bluetooth無効、許可拒否、候補なしを成功と混同しないことも確認します。
開発用実行と本番バンドルでの権限確認を区別します。

### パーサーと受信

[プロトコルの既知パケット](protocol.md)を使い、
長さ・checksum・statusなど、そのプロファイルの検証条件を確認します。
受信した通知に対して、機器に対応するプロファイルを選んで実機の値と一致することを確かめます。
共通の収集・保存処理が特定機種に依存せず、異なる形式を誤ったパーサーへ渡さないことも確認します。

パーサーのテスト成功と、BLE経由で受信できたことは別の結果として記録します。
未確認の履歴候補や未知の機種を確定測定として扱いません。

### 保存と記録アクセスCLI

SQLiteライブラリの採用時には、必要な機能とnative互換性を確認します。
受信から保存・参照まで、CLI出力と永続化された記録を検証します。

必要なシナリオは、安定値、重複受信、同じ体重の別測定、未知パケット、保存失敗です。
書き込み失敗時に確定結果だけが残らないことと、成功扱いしないことを確認します。
収集を停止してもCLIで既存記録を読めることを確認します。

### 常駐動作

実際に配布するバンドルで、初回Bluetooth許可、サービスの登録・解除、
ログイン起動、異常終了からの再起動、停止・再開、スリープ復帰を確認します。
再起動後にプロセスや接続が二重にならず、停止時に受信済みデータの保存が完了することを
確かめます。`service status`の表示と実際の状態も照合します。

常駐中のCPU、メモリ、消費電力、検出から接続までの時間、測定取得の成功率を記録します。
スキャン方針の比較では同じ体重計・Mac・条件を使い、測定条件と試行回数を残します。
数値のない段階で低消費電力や低メモリを保証しません。
