# AnkerScaleの設計

## 目的と現在地

AnkerScaleは、体重計からBLE経由で測定値を取得してローカルに記録し、
CLIから履歴を参照・出力するmacOS向けの道具です。
初期構成はGUIを持たない常駐収集とCLIとし、MoonBitを主言語にします。

現在の実装はnativeを既定ターゲットにしたMoonBitのひな形です。
以下はこれから実装する設計であり、BLEや常駐動作の実証結果ではありません。

## 初期スコープ

- ログイン中に体重計の起動を待ち受け、接続して測定値を保存する。
- 機種ごとの通信条件をプロファイルとして扱う。対応範囲と検証条件は[プロトコル](protocol.md)に記載する。
- 最新結果、期間を指定した履歴、JSON・CSV出力をCLIで提供する。
- rawパケットと解析エラーを残し、測定結果の根拠を追跡できるようにする。
- Bluetoothの無効化、接続失敗、スリープ復帰、明示的な停止を扱う。
- 保存と参照をローカルで完結させる。

GUI、クラウド同期、公式アカウント連携、体組成計算、ユーザー自動判定は初期スコープに含めません。
対象機器が複数見つかる場合の選択方法は、常駐化の前に決めます。

## 構成と責任

```text
launchd
  └─ 収集プロセス
       ├─ MoonBit: 機種判定、測定状態、再試行方針、解析、保存
       └─ Objective-C: CoreBluetooth操作とイベントの受け渡し
              ↕ 体重計

収集プロセス ── 書き込み ── SQLite ── 読み取り ── MoonBit CLI
```

| 部分 | 担当 | 責任 |
| --- | --- | --- |
| 通信規則 | MoonBit | パケット解析、初期化コマンド生成、測定の判定 |
| 収集制御 | MoonBit | 接続状態、期限、再試行、停止、イベントの順序 |
| macOS接続層 | Objective-CとC ABI | CoreBluetooth操作、OSの結果を値に変換して返す |
| 保存とクエリ | MoonBitとSQLiteバインディング | トランザクション、重複排除、履歴の読み取り |
| 操作入口 | MoonBit CLI | 引数、表示、終了コード、JSON・CSV出力 |
| 起動管理 | launchdとService Management | ユーザー単位の起動・停止と登録状態 |

MoonBitから外部の関数を呼ぶ境界にはC FFIを使います。
Objective-C側はC ABIの関数を公開し、同じ収集プロセスへリンクします。
接続層へ体重計の解析や保存方針を持ち込まず、別のBLEヘルパープロセスも設けません。
この構成は[MoonBitのC FFI](https://docs.moonbitlang.com/en/latest/language/ffi.html)
を基にした案であり、CoreBluetoothとのリンク・イベント連携は最小実装で検証します。

最初から汎用プラグイン基盤や大量のパッケージを用意せず、実装された責任に応じて分割します。

## 機種ごとのプロトコル

通信形式を共有する機種群ごとに、
候補の判定条件、GATT構成、初期化手順、パケット解析をプロファイルへまとめます。
異なる通信形式を一つのパーサーへ押し込まず、測定結果を共通の型へ変換します。
収集制御、保存、CLIはこの共通の型を使い、特定機種のバイト列へ依存しません。

対応を追加するときは、そのプロファイルのパケット例と実機での検証結果を記録します。
同じUUIDや似た名前だけで互換性を判断せず、未判定の機器に既知機種のコマンドを送信しません。
未対応機種の情報は調査用として扱い、対応済みの測定結果に混ぜません。

## BLEと実行順序

基本の流れは、停止、Bluetooth待機、検索、接続、通知購読、測定、切断です。
Bluetoothがオフの場合と権限がない場合は区別し、接続失敗は期限付きの再試行へ戻します。
停止中は新しい接続を開始せず、受信済みデータの処理と切断を終えてから停止を確定します。

CoreBluetoothのオブジェクトは専用の直列キューに閉じ込めます。
イベントは順序を保ってMoonBit側へ渡し、OSのコールバックから任意のスレッドで
MoonBitのオブジェクトを操作しません。具体的な受け渡し方式は検証段階で決めます。
バイト列の所有権、コールバックの寿命、停止後に到着するイベントの扱いを明示します。

検出イベントを受けたら接続判断を行い、固定時間の終了まで機器一覧の確認を待ちません。
スキャンを継続するか間欠的にするかは、取得成功率・接続時間・消費電力で判断します。
GUIの有無には連動させません。
サービスUUIDを広告に載せない機器を除外しないよう、フィルター条件も実機で確かめます。

待機列が満杯の場合や保存に失敗した場合に、rawを黙って破棄したり成功扱いしたりしません。
待機列の上限、エラー時の収集停止と再開方法は、保存処理の実装時に確定します。

## データと保存

収集プロセスが通常運用中の唯一の書き手です。CLIは読み取り専用でDBを開きます。
収集が停止していても、保存済み記録へのアクセスは継続できます。
WALモードで並行読み書きを扱い、同じユーザーのローカルディスクへ置きます。
読み取りトランザクションを開いたまま待機しないようにします。
詳細は[SQLiteのWAL仕様](https://sqlite.org/wal.html)を参照してください。

| データ | 保持する情報 |
| --- | --- |
| 機器 | ホスト内の識別子、名前、観測したサービス、初回・最終検出時刻 |
| rawパケット | 機器、接続セッション、連番、方向、時刻、characteristic、バイト列 |
| 解析結果 | パーサーの版、認識した種別、失敗理由、未確認の候補であること |
| 確定測定 | 安定した体重、測定時刻、出典、元のrawへの参照 |

rawと、そこから得られる確定測定は同じトランザクションで保存します。
解析不能・未知・重複のパケットもrawとして残します。
保存が完了するまで「記録済み」として扱いません。
初期版でrawを自動削除する既定値は設けず、保存量を確認して保持方針を決めます。

測定中の値と過荷重は確定履歴に混ぜません。rawからは追跡可能にします。
体重は整数単位で正確に保持し、表示時にkgへ変換します。
保存時刻はUTCで統一し、端末から受け取った測定時刻とは区別します。
日時が不正・不明なパケットを現在時刻の測定として補完しません。

重複排除は、同一機器の測定内容と短い受信時間差に基づいて行います。
同じ体重というだけで別の測定を消さず、再接続直後の再送も検証対象にします。
受信間隔には単調時計を用い、履歴用の日時と混同しません。

SQLiteライブラリはまだ採用しません。
[mizchi/sqlite](https://mooncakes.io/docs/mizchi/sqlite)などを候補に、
native互換性、読み取り専用接続、トランザクション、NULL、資源解放、エラー伝播を確認します。

## CLIの操作案

次のコマンドは未実装の案です。現在の実行方法は[開発手順](development.md)を参照してください。

```sh
ankerscale latest
ankerscale history --since 2026-09-01
ankerscale history --since 2026-09-01 --json
ankerscale export --format csv
ankerscale service status
ankerscale service start
ankerscale service stop
ankerscale logs
```

通常出力は人向け、JSONは機械処理向けとし、診断メッセージは標準エラーへ出します。
日時の境界・タイムゾーン、空の履歴、JSONの形、終了コードはCLI実装前に定義します。

記録取得のためのHTTPサーバーやRPCは設けません。
サービスの起動状態と、実際に測定を保存できていることは別々に表示します。
最新記録が古いことだけで障害と断定せず、プロセスの存在だけで収集正常とも判定しません。
ライブの接続状態が必要になった場合だけ、その用途に限定したプロセス間通信を検討します。

## 常駐と権限

ユーザーのログイン中に動くLaunchAgentを使い、rootのLaunchDaemonは使いません。
Macのスリープ中やログアウト中の取得は保証対象にせず、復帰後の再開を検証します。

GUIを持たないアプリバンドルを、識別子・権限説明・署名・サービス登録の単位とする案を
第一候補にします。CLIへの入口、初回の権限要求、更新時の扱いはまだ未確定です。
[AppleのGUIなしLaunchAgentサンプル](https://developer.apple.com/documentation/ServiceManagement/updating-your-app-package-installer-to-use-the-new-service-management-api)
を参考にし、Bluetoothの許可がどの実行ファイルへ付与されるかを実機で確認します。
[Bluetoothの用途説明](https://developer.apple.com/documentation/bundleresources/information-property-list/nsbluetoothalwaysusagedescription)
もアプリの実際の用途に合わせて設定します。

GUIなしでは障害に気づくための確認が必要になります。
まずCLIの状態表示とログを整え、必要性が確認されたら状態・最新値だけの
メニューバーUIや通知を検討します。追加するUIに収集プロセスの寿命を所有させません。
